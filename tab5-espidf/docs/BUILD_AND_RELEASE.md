# Building, flashing, CI and releases

## Supported baseline

- Target: **ESP32-P4 / M5Stack Tab5**, with ESP32-C6 used as hosted radio companion.
- ESP-IDF: **v5.5.4** (the baseline used during the source investigation).
- The `sdkconfig` and `sdkconfig.defaults` are tracked on purpose. The `dependencies.lock` pins managed components. Do not casually upgrade any of these during failure isolation.
- Only the *P4* is programmed with the commands here. The C6 companion's firmware is a separate dependency; verify its provenance and compatibility before attempting upgrades.

## Build from this directory

All commands below run from `tab5-espidf/` (this is the ESP-IDF project root; the repository root one level up also holds the unrelated ESP32-S3 PlatformIO source tree):

```sh
. "$IDF_PATH/export.sh"       # if your ESP-IDF install requires it
python3 -m unittest discover -s tests -v
python3 tools/check_source_tree.py
idf.py build
python3 tools/check_hosted_init.py --strict
idf.py merge-bin -o tab5-bitpirate-full.bin
python3 tools/package_firmware.py --build-dir build --out-dir dist
```

The top-level `CMakeLists.txt` invokes `tools/apply_vendor_overrides.py` **after managed-component resolution**, with `COMMAND_ERROR_IS_FATAL ANY` so a failed override check aborts the configure step. Eight managed source overrides are SHA-256 guarded against pristine locked versions in `tools/vendor_overrides_manifest.json`; a changed upstream file must be reviewed before bumping the expected hash. Never copy an arbitrary replacement into `managed_components/` or bypass a failed check merely to get a build passing. See `tools/vendor_overrides_manifest.json` for the exact paths and hashes, and `tools/apply_vendor_overrides.py`'s own header comment for how to re-capture it after a deliberate `dependencies.lock` bump.

## Flashing

For ordinary development, use the **USB-C Serial/JTAG** interface:

```sh
idf.py -p /dev/ttyACM0 flash monitor
```

For release artifacts, `dist/FLASHING.txt` and `dist/flasher_args.json` give the exact offsets generated by the build. After `idf.py merge-bin`, the merged image can normally be flashed at `0x0` (always verify it against your chip and manifest first). Do not use USB-A HID/CDC enumeration as evidence that the P4 ROM downloader is active. For recovery use the manufacturer's documented BOOT/RESET procedure; **no reliable automatic `usbboot` entry has been qualified**.

**Back up any irreplaceable NVS, saved presets and SD content before full-flash operations.** A build here is source-built, not a prebuilt M5Burner image; a passing GitHub Actions build does not prove M5Burner or browser flasher compatibility. Those distribution paths need independent tests.

## GitHub Actions

Only two of the repo's workflows touch this directory (both set `working-directory: tab5-espidf`); the rest (`native-tests.yml`, `firmware-resource-delta.yml`, `upstream-firmware-delivery.yml`, `weekly-firmware-health.yml`) are for the ESP32-S3 PlatformIO side at the repo root and don't build or test this port.

- `build-tab5-espidf.yml`: static checks, host-side tests, IDF build and artifact packaging on push/PR/manual dispatch.
- `release-tab5-espidf.yml`: manually rebuilds an existing version tag and publishes an explicitly marked **prerelease** with the separate and merged flash images, enforcing `check_hosted_init.py --strict`.

## Release minimum

1. A fresh, reproducible IDF build and strict managed-dependency validation.
2. Host tests and packaging tests pass; all required artifacts and SHA-256 sums present.
3. A verified flash/recovery procedure and tested board boot/console.
4. Mode-by-mode protocol tests with real tools and known external devices, as shown in `FEATURE_PARITY.md`.
5. No accidental use of `USB5V_EN` in a Device-role session, and no local FAT/MSC concurrent ownership.
6. Document hardware sample and firmware versions used for qualification, without publishing private eFuse dumps, MAC addresses, SSIDs or other identifiers.

Thermal and endurance work is deferred by project decision, not silently regarded as passed.
